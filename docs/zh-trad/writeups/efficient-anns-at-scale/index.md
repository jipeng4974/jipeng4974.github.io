# 高性能大規模向量檢索

> 如何在十億、百億級特徵庫上做高效的向量檢索

---

LLMS index: [llms.txt](/llms.txt)

---

向量檢索分爲KNN和ANN，KNN就是用brute-force計算出query向量和所有索引向量的相似度，取前k個。ANN則是通過近似手段加速計算，以誤差換效率。

如何做高效的向量檢索？方法有二，一是提升編碼率（不僅能降低內存佔用，也能加速計算，因爲便於SIMD且減少訪存）的量化（IVF向量量化、PQ量化、ScaNN各向異性量化、4bit量化），二是縮小搜索空間的圖搜索（HNSW）。

如何在十億、百億級特徵庫上做向量檢索？主要挑戰是索引無法放入內存，因而需要考慮內存-磁盤混合方案（SPANN）。

本文只介紹一小部分有效且正交的技術，這些技術組合在一起可形成當前的最佳實踐。其他一些古典、經典技術可以參考本文引用的論文的背景綜述。

# 相似度
首先回顧一下什麼是**向量之間的相似度**:
- 對向量X和Y來說，x和y越接近，則x越大的地方y也大，x小的地方y也小，則內積越大。因此內積可用作相似度打分，不過不能抵抗尺度變化。
- 爲了抵抗尺度變化，往往將內積正則化到[-1,1]，就變成了餘弦相似度cosθ，θ爲向量夾角，顯然θ越小，向量越接近。
- 歐幾里得距離正則化到[-1,1]後相當於sqrt(2-2cosθ)。可見歐式距離平方也是和餘弦相似度成比的。

![sim_measure](https://wujipeng.com/img/sim_measure.png)

正則化後歐式距離、內積、cosθ三者同源，所以我們一般就用餘弦相似度cosθ去度量向量/embedding之間的相似程度。除非又特殊的抵抗位置變化的需求，可採用皮爾森相關係數，皮爾森相關係數是協方差（兩個變量的總體誤差）的正則化，不過它同時也可以被視爲將x和y中心化後的餘弦相似度。

# 向量量化
量化器是D維向量 x  ∈ R^D 到 q(x) ∈ C = {c_0, c_1, ... c_k-1} 的映射函數q。c_i即聚類中心centroid。
所謂密碼本（codebook）就是一個lookup table，用centroid下標作爲原始向量的低bit表示，密碼本大小就是k。

向量量化本質是有損壓縮，表徵學習本質上也是有損壓縮，一個白盒，一個黑盒，都是試圖降低高維數據的編碼率。

# IVF：聚類、倒排、剪枝
倒排（特指IVF）是一種古老的量化技術，早期應用於[Video Google](https://www.robots.ox.ac.uk/~vgg/publications/2003/Sivic03/sivic03.pdf)。核心思想是基於k-means聚類做向量量化。k-means聚類起源於信號處理領域，目標是把n個向量分區到k個clusters，每個向量屬於離centroid最近的cluster。

聚類後有些邊緣數據點既屬於A，也屬於B，那就把它同時放到A和B的centroid對應的postinglist裏面去，不過重複放置會導致postinglist膨脹，爲了應對這種膨脹，可採取剪枝策略，具體可參考微軟的SPTAG項目和[SPANN論文](https://arxiv.org/pdf/2111.08566.pdf)。

Faiss的IVFFlat就是在聚類形成centroid爲term的倒排後提供檢索能力，nlist爲聚類數，nprobe爲臨近centroid探測數，nprobe=nlist時退化爲暴搜。IVFFLat在檢索時將query鄰近的nprobe個centroid對應的所有原始向量作爲搜索空間進行暴搜。由於centroid的表示方式可以簡化成clusterid，所以實際上IVF也是一種量化：用一個數組存放所有的centroid向量，數組下標即可表示centroid。

# PQ：乘積量化
基於聚類的量化對低維向量比較有效，但隨着向量維度升高，出現誤差也變高，而且這種誤差不是提升聚類數目能解決的。如果把聚類數目（codebook大小）提升到2^64，訓練這個聚類的開銷就會高得無法接受，需要數倍於2^64的樣本，內存顯然也放不下。**乘積量化（PQ）**就是降維手段解決IVF量化誤差的技術，[Jegou et al., 2011](https://lear.inrialpes.fr/pubs/2011/JDS11/jegou_searching_with_quantization.pdf)以及[ScaNN](https://arxiv.org/pdf/1908.10396.pdf)均討論了PQ。其核心思想是對索引數據量化，將d維空間切分爲M個子空間，將高維向量的誤差擬合爲分段的低維向量誤差之和。

乘積量化中，IVF倒排鏈存的不是原始向量，而是原始向量的一種編碼：
- 求原始d維向量與高維粗聚類centroid的殘差（殘差的目的是中心化，讓數據點分佈變得更集中，使精度更好）
- 將殘差向量切成M個分段，每個分段維度爲d/M
- 每個分段做$k=2^n$個細聚類，n即爲低維細聚類clusterid的編碼長度，4bit或8bit
- 用每個分段的鄰近低維細聚類centroid去量化該分段上的原始殘差分段

Faiss的IVFPQ就結合了IVF和PQ，IVF粗聚類是一級量化，PQ則是二級量化。一方面索引體積減小，另一方面計算上也只需要計算殘差和分段細聚類centroid近鄰的距離，還能SIMD加速，性能收益非常顯著。不過IVFPQ的distance究竟只是一種擬合，是距離粗聚類centroid的距離加上M個分段裏query殘差和鄰近細聚類centroid的距離總和，這種擬合可以一定程度上幫助找到近鄰，但不適合用作距離，可以把IVFPQ當做粗排，結果再做一次brute-force或高精度ANN重算，得到更精確的距離。

ScaNN提出了各向異性量化，算是正本清源，糾正了此前就近選擇centroid在數學上的錯誤，並且實踐了4-bit量化取得非常好的效果（其實4bit量化的效果還比各向異性更大，但各向異性在理論上貢獻更大）。傳統的量化把數據點量化到離自己最近的聚類中心，但這麼做未必是誤差最低的，越平行的向量之間內積越大，越正交的向量之間內積越小，因此賦予平行向量更高的誤差懲罰權重效果更好。這就意味着不一定量化到距離最近的centroid了，目標是整體編碼率不變的前提下，讓平行方向量化誤差更小，正交方向誤差高一些其實無所謂，從而提升整體的ANN效果。

假設d/M = 4，採用8bit量化，原始向量是256維f32向量，則PQ將256個float32壓縮到64個int8，內存減少到1/16。乘積量化顯然可以顯著減少內存和存儲開銷，其實這也能加速計算，原因如下：
- 高效點乘（其實也是誤差換效率）：O(dk+mn) 比 O(nd)快，d維度的query和n個量化後的向量點乘，引入m個大小爲k的量化codebook，mn可以忽略不計，k遠小於n。
- memory bandwidth：現代處理器需要“高計算量per memory read”才能充分發揮硬件的計算性能。量化壓縮數據點後內存帶寬的使用也下降了，變得更計算密集。
- 向量量化中引入的低bit表示，尤其是4bit量化，和低bit浮點數量化一樣，可以享受SIMD、AMX的性能紅利。

# 最佳實踐：根據應用場景將各種正交技術進行正確組合
HNSW、IVF、PQ、各向異性的score-aware quantization loss、brute-force事實上都是正交的技術，可以組合起來使用。

比如進行了PQ量化的數據點可以再構建一個HNSW，用圖方法在超大規模數據集上做查詢顯然比ivfpq更高效。各向異性量化則是對此前PQ量化的修正。考慮到量化後的距離失真，還能用brute-force把ivf+pq+hnsw的粗排結果重算一下得到最精確的距離，由於已經經過一輪粗排，候選數據集大小從十億級別縮小到萬級別，brute-force的開銷就完全可以接受了。
