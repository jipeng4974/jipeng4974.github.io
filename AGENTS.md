the theme repo is available as a sibling ../oink, only edit oink theme when it's necessary. 
source ~/.zshrc to add hugo and go to $PATH
photos section pages use progressive image loading: layouts/_markup/render-image.html wraps every image of each photos page in placeholder frames, assets/js/photo-gallery.js (injected via layouts/_partials/hooks/body-end.html) fetches them on scroll with a concurrency cap, streamed download progress and retries, and adds a fullscreen lightbox (click to open, prev/next arrows, ESC/X/backdrop to close, live progress for pending photos); styles live in assets/scss/_styles_project.scss

photos section pages also have a rectangular thumbnail guide above the originals: layouts/_partials/photo-guide.html emits ordered photo URLs plus dimensions from generated data/photo_metrics.toml, and assets/js/photo-guide.js deterministically partitions the photos into variable-height mosaic rows; clicking a tile scrolls to its corresponding progressive-loading frame. Guide thumbnails load eagerly and photo-guide.js exposes photoGuideReady; photo-gallery.js waits for that promise before starting original downloads. Thumbnails are expected at https://assets.wujipeng.com/thumbs/<stem>.jpg. After adding/changing photos, prepare the local thumbnail manifest and run scripts/generate-photo-metrics.py.

Photo presentation is decided by the viewport at runtime (no configuration): portrait-aspect screens (phones) get the legacy tiled `mosaic` flow, everything else gets `stacked` — OpenAI-style sticky cards inside one shared tall scroll group (photo-guide.js applies `photo-mode-stacked`/`photo-mode-mosaic` on `.td-content`). Thumbnail jumps target invisible stack anchors and prioritize the target original.
pages with display math auto-fit it to the screen: assets/js/math-fit.js (injected via layouts/_partials/hooks/body-end.html when .Page.Store hasMath) scales each .katex-display down via font-size until it fits its container, with a minimum scale beyond which horizontal scrolling takes over (overflow fallback in assets/scss/_styles_project.scss)
the right TOC rail (On this page / Tags / Actions) stays a rail at every width instead of moving into the left drawer below xl (layouts/_partials/shell/sidebar-panel.html removes the drawer slot): below md its toggle lives in the mobile topbar (layouts/_partials/shell/subnav.html, "text" list icon, distinct from the drawer's "panel-left"), between md and xl the floating restore button shows (assets/scss/_styles_project.scss restricts .td-shell-toc-float to that range so it can't overlap the topbar); on phone portrait the rail opens as a full-width top sheet below the 56px subnav (~60dvh, translucent — assets/scss/_styles_project.scss). Its icon row is one line: quick links left, the actions (email, RSS, language, theme) and the close button right — close sits last so the row is symmetric with the sidebar's own close on the other side — and the sheet's group switch is a segmented pill (contents / tags / actions) centred between the two groups, which are equal-width flex items, so no spacer element is needed (layouts/_partials/shell/toc-aside.html + assets/js/toc-sheet.js). Pressing a segment opens its group and closes the others. The sheet opens on contents wherever that group has something to show (a heading tree or a section's child list) and on actions for a heading-less article, so no page lands on an empty sheet; a page with neither a heading tree nor child pages drops the contents segment entirely. Below ~420px the pill drops to its own centred line instead of colliding with the ten icons. The left drawer is gone below md, not just hidden: the subnav's drawer button was removed and the sidebar panel + backdrop are display:none (assets/scss/_styles_project.scss), so the drawer footer's global actions moved into the sheet's icon row as sheet-only buttons (email, RSS; .td-shell-sheet-extra), and in-section navigation comes from the contents group listing a section's child pages (layouts/_partials/shell/section-pages.html) since those pages have no heading tree of their own; tapping the content below still closes the sheet (assets/js/toc-sheet.js, injected via layouts/_partials/hooks/body-end.html, plus a .td-shell-toc-sheet-backdrop element in toc-aside.html).

the gamedemo shortcode (layouts/_shortcodes/gamedemo.html) embeds playable Godot web builds: `{{< gamedemo src="https://assets.wujipeng.com/games/<name>/<version>/index.html" play="Play the demo" >}}` renders a play button that opens a fullscreen dark overlay with an iframe whose src is set only on click (no eager wasm download); ESC/X closes it, clears the iframe src, and restores body scroll; inline JS/CSS is emitted once per page via a .Page.Store guard. Game builds (index.html/js/wasm/pck from the Godot Web-nothreads export) are uploaded to the R2 bucket behind assets.wujipeng.com under `games/<name>/<version>/` — never into static/, because the wasm (~38 MB) exceeds Cloudflare's 25 MiB per-file static-asset limit and would make every deploy fail; the wasm object must carry Content-Type: application/wasm metadata

the TOC rail's Actions group is a project override (layouts/_partials/page-meta-links.html): the theme's "Print this page" button is gone, "Copy link" (the address bar URL, anchors included) and "Copy BibTeX" were added, and the section-level print output — one continuous page holding the whole section — is relabelled "Enter scroll mode" (i18n key ui_scroll_mode). The two clipboard actions live in assets/js/page-actions.js (injected via layouts/_partials/hooks/body-end.html) and reuse the theme's copy feedback contract, which docs-shell.js implements for the untouched "Copy Markdown" button: `.is-copied` on the button swaps its icon for a check, the `[data-td-page-copy-label]` span flashes the button's data-t-copied text, and the group's aria-live `[data-td-page-context-status]` announces it — change that contract in both files together. The BibTeX `@online` entry is assembled in JS from data-bibtex-* attributes the partial fills from params.citation in hugo.yml (author, key_prefix → cite key `<prefix>-<page slug>`) plus the page title/date/permalink; undated pages (section indexes) ship empty year/month and those fields are dropped. The link and braces glyphs are inlined in the partial rather than added to the theme's icon dispenser.

In writeups, English version has no suffix, Chinese version has suffix .zh.md.

Writeup article pages open with one meta line instead of the theme's byline + "Tags:" blocks: layouts/blog/_td-content.html renders `<header class="article-meta article-meta-row">` with the date (en `Sept. 17, 2026`, zh `2026年9月17日`), the tag chips and the italic AI-assisted note, and assets/scss/_styles_project.scss sizes the whole row from one `--article-meta-band` (0.75rem text) so the chips sit on the date's baseline — resetting the theme's `.td-content ul li` bottom margin is required for that, otherwise the chips float 4px high. Chips carry no "Tags:" label, their hue comes from `hash.FNV32a` of the tag name (collisions nudged to the next free slot) mapped onto the cool `.article-tag--t0..t7` ramp, and the pointed left tip is an absolutely positioned `clip-path` triangle while the shadow is a `drop-shadow` on the `<li>` (box-shadow would miss the tip). The zh AI note reads its string from i18n/zh-cn.yaml, not zh.yaml: the zh site's locale (zh-CN) selects the regional i18n file.

Page headings in writeups/works/photos/about/gears place the description next to the h1 as a one- or two-line deck (layouts/_partials/page-heading-desc-fit.html decides, `.td-page-heading` in assets/scss/_styles_project.scss renders): the description box flexes from 22em up to 34em, and when the row cannot hold even 22em it wraps under the title with a row-gap (same shape as block mode). Inline vs block comes from measured text widths — title 12.8px per Latin char / 28px per CJK char (Georgia 28px bold), description 6.7 / 16 (Georgia 16px) — against a 940px row budget (the 1050px article max-width minus its 2 × 48px padding); a description needing more than two lines of the box it can actually get goes to block mode, so keep those constants in sync with the CSS if either width changes.

Tag chips are a shared partial (layouts/_partials/article-tags.html, styled by `.article-tag` / `.article-tag-list` in assets/scss/_styles_project.scss) used by both the writeup article meta row and the writeups list cards, so a tag looks the same in either place; the writeups list (layouts/partials/blog-list-main.html, also the homepage list) renders date + section + chips + the italic AI hint in one `.td-blog-posts-list__meta` row, with no separate "Tags:" line. The chips have a fixed 0.75rem label and take their box height from `--article-meta-band` (1.125rem, set by each row), which is what keeps them on the neighbouring text's baseline; the li margin reset must stay scoped through those two row classes to outrank the theme's `.td-content ul li`. The tag term pages (shell/blog-row.html) still show no chips.
