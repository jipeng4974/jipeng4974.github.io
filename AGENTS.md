to build this project, make b or make p, see Makefile
the theme repo is available as a sibling ../oink, only edit oink theme when it's necessary. 
source ~/.zshrc to add hugo and go to $PATH
photos section pages use progressive image loading: layouts/_markup/render-image.html wraps every image of each photos page in placeholder frames, assets/js/photo-gallery.js (injected via layouts/_partials/hooks/body-end.html) fetches them on scroll with a concurrency cap, streamed download progress and retries, and adds a fullscreen lightbox (click to open, prev/next arrows, ESC/X/backdrop to close, live progress for pending photos); styles live in assets/scss/_styles_project.scss

photos section pages also have a rectangular thumbnail guide above the originals: layouts/_partials/photo-guide.html emits ordered photo URLs plus dimensions from generated data/photo_metrics.toml, and assets/js/photo-guide.js deterministically partitions the photos into variable-height mosaic rows; clicking a tile scrolls to its corresponding progressive-loading frame. Guide thumbnails load eagerly and photo-guide.js exposes photoGuideReady; photo-gallery.js waits for that promise before starting original downloads. Thumbnails are expected at https://assets.wujipeng.com/thumbs/<stem>.jpg. After adding/changing photos, prepare the local thumbnail manifest and run scripts/generate-photo-metrics.py.

Photo presentation is decided by the viewport at runtime (no configuration): portrait-aspect screens (phones) get the legacy tiled `mosaic` flow, everything else gets `stacked` — OpenAI-style sticky cards inside one shared tall scroll group (photo-guide.js applies `photo-mode-stacked`/`photo-mode-mosaic` on `.td-content`). Thumbnail jumps target invisible stack anchors and prioritize the target original.
pages with display math auto-fit it to the screen: assets/js/math-fit.js (injected via layouts/_partials/hooks/body-end.html when .Page.Store hasMath) scales each .katex-display down via font-size until it fits its container, with a minimum scale beyond which horizontal scrolling takes over (overflow fallback in assets/scss/_styles_project.scss)
the right TOC rail (On this page / Tags / Actions) stays a rail at every width instead of moving into the left drawer below xl (layouts/_partials/shell/sidebar-panel.html removes the drawer slot): below md its toggle lives in the mobile topbar (layouts/_partials/shell/subnav.html, "text" list icon, distinct from the drawer's "panel-left"), between md and xl the floating restore button shows (assets/scss/_styles_project.scss restricts .td-shell-toc-float to that range so it can't overlap the topbar); on phone portrait the rail opens as a full-width top sheet below the 56px subnav (~40dvh, translucent — assets/scss/_styles_project.scss) with Tags/Actions collapsed by default and tap-on-content to close (assets/js/toc-sheet.js, injected via layouts/_partials/hooks/body-end.html, plus a .td-shell-toc-sheet-backdrop element in layouts/_partials/shell/toc-aside.html)

the gamedemo shortcode (layouts/_shortcodes/gamedemo.html) embeds playable Godot web builds: `{{< gamedemo src="https://assets.wujipeng.com/games/<name>/<version>/index.html" play="Play the demo" >}}` renders a play button that opens a fullscreen dark overlay with an iframe whose src is set only on click (no eager wasm download); ESC/X closes it, clears the iframe src, and restores body scroll; inline JS/CSS is emitted once per page via a .Page.Store guard. Game builds (index.html/js/wasm/pck from the Godot Web-nothreads export) are uploaded to the R2 bucket behind assets.wujipeng.com under `games/<name>/<version>/` — never into static/, because the wasm (~38 MB) exceeds Cloudflare's 25 MiB per-file static-asset limit and would make every deploy fail; the wasm object must carry Content-Type: application/wasm metadata

In writeups, English version has no suffix, Chinese version has suffix .zh.md.

Writeup article pages open with one meta line instead of the theme's byline + "Tags:" blocks: layouts/blog/_td-content.html renders `<header class="article-meta article-meta-row">` with the date (en `Sept. 17, 2026`, zh `2026年9月17日`), the tag chips and the italic AI-assisted note, and assets/scss/_styles_project.scss sizes the whole row from one `--article-meta-band` (0.75rem text) so the chips sit on the date's baseline — resetting the theme's `.td-content ul li` bottom margin is required for that, otherwise the chips float 4px high. Chips carry no "Tags:" label, their hue comes from `hash.FNV32a` of the tag name (collisions nudged to the next free slot) mapped onto the cool `.article-tag--t0..t7` ramp, and the pointed left tip is an absolutely positioned `clip-path` triangle while the shadow is a `drop-shadow` on the `<li>` (box-shadow would miss the tip). The zh AI note reads its string from i18n/zh-cn.yaml, not zh.yaml: the zh site's locale (zh-CN) selects the regional i18n file.
